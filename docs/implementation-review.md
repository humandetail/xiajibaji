## Spec

独立评审最初发现两项 P2，均已修正：

1. 事务写入完成后再读回，若读取失败会误报保存失败，新记录重试可能产生重复；删除也可能误报记录已保留。现在保存、删除和撤销在事务完成后直接更新内存结果，成功反馈不依赖额外读取。新增浏览器测试先复现，再验证刷新后只保存一条。
2. 恢复使用包含“不得晚于今天”的日期校验，导致跨时区后自己的有效备份可能被拒绝。现在备份恢复只验证民用日期本身，保持所属日期；新增和移动仍限制为今天及过去。原所属日期在落后时区暂时落到未来时仍可查看并修改原记录，但不能借此新增未来记录。新增洛杉矶与上海时差场景回归测试。

评审者静态复核后确认两项已解决，未发现修改引入的新实质问题。主流程的浏览器回归测试通过。

## 后续修复：恢复提交后读取失败

再次代码评审发现：恢复事务提交后，回调重新读取数据库；读取失败被启动逻辑吞掉，界面保留恢复前的记录，却提示恢复成功。用户编辑旧记录时会把它重新写入数据库。

修复为事务提交后直接将已校验、已写入的备份记录传给界面，替换内存记录并重新渲染；同时清理旧的删除撤销状态与提示定时器。恢复成功反馈不再依赖第二次读取。离线外壳缓存版本同步更新。

新增浏览器故障回归，先复现失败再修正：恢复前备份下载完成后令只读事务失败，检查旧记录入口消失、备份内容可见；继续编辑恢复后的记录，等待保存完成再刷新，确认旧记录没有重新出现。共享新增记录测试步骤也统一等待保存确认，避免在事务完成前关闭或刷新页面。

验证结果：恢复故障与离线关闭重开场景各连续运行三次，6/6 通过；最终全套 12/12 浏览器测试通过（1.1 分钟）。严格类型检查、格式检查和 diff 检查通过。本次评审发现的 P2 已修复。

## 后续修复：取消安装后的失效按钮

取消安装会消耗浏览器提供的一次性请求；原实现清空请求后仍显示按钮，再次点击静默返回。现在点击时先保存当前请求、清空待处理请求并隐藏按钮，随后发起安装；取消与异常都不会留下失效入口，异常保留菜单安装指引。新的 beforeinstallprompt 事件可重新显示按钮，旧请求结束也不会清掉新请求。离线外壳缓存版本同步更新。

新增浏览器系统事件边界测试，先复现取消后按钮仍可见，再验证取消、新请求接受与调用异常三种路径。此验证使用安装事件模拟，不声称覆盖手机原生安装弹窗。

验证结果：针对回归通过，最终全套 13/13 浏览器测试通过；严格类型检查、格式检查及 diff 检查通过。本次评审发现的 P3 已修复。
