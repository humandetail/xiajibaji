# 瞎JB记：移动端本地日历随手记

Status: ready-for-agent

确认日期：2026-11-04。用户已确认本地 Markdown + AGENTS.md 配置及浏览器行为测试入口。

## Problem Statement

用户希望用手机随手记下运动或其他生活中的事情，不想为每次记录分类、填写固定指标或建立账号。一天下来可能发生多件事，事后还需要修改或补记。普通文字列表难以直观看出一个月哪些天有记录、共记了多少条、每天做了什么。

用户还需要把月度内容带走：既能生成清楚、可保存分享的图片，也能复制纯文字或下载文字文件。内容由用户在本地持有，断网仍能使用，并能通过备份迁移或找回记录。

## Solution

提供名为“瞎JB记”的移动端 Web 应用，以月历作为首页。选择今天或过去的一天，新增一条自由文字记录；同一天可有多条，每条可修改、调整日期或删除。首页以原文短摘要标出有记录的日期，下方展示所选日期的完整记录，上方显示所选月份的记录天数和记录条数。

提供月度回顾导出：默认包含所选月份全部记录，可预览并排除不想导出的内容；图片包含月历、次数概览和按日期排列的完整记录，过长时拆成多张；文字导出支持复制及下载 .txt。备份和恢复是独立的数据管理功能，不以分享图片或文字代替可恢复的数据。

视觉延续已完成的纸感设计：暖白纸底、墨黑正文、酸橙色强调，月份使用宋体，日常操作使用系统中文黑体。以日历和记录为主角，不引入打卡压力、强制分类或目标。

## User Stories

1. 作为手机用户，我希望打开应用就看到当前月份的日历，以便立即定位今天和本月记录。
2. 作为记录者，我希望切换月份并能返回今天，以便回看历史和继续当天记录。
3. 作为记录者，我希望在月历上辨认哪些日期有记录，以便快速回顾生活分布。
4. 作为记录者，我希望每个日期格露出前两条记录的简短原文，以便不用逐日打开也能知道大概记了什么。
5. 作为记录者，我希望超过两条时看到“另 N 条”，以便知道当天还有内容。
6. 作为记录者，我希望点击日期后看到当天完整记录，以便读清被月历截断的文字。
7. 作为记录者，我希望看到本月记录天数，以便知道有多少天留下过记录。
8. 作为记录者，我希望看到本月记录条数，以便知道共记了多少次事情。
9. 作为记录者，我希望同一条文字提到多件事仍只计一条，以便统计口径保持稳定。
10. 作为记录者，我希望用自由文字记运动和其他生活琐事，以便不用适应固定分类。
11. 作为记录者，我希望文字支持换行，以便写下多句内容或简单列表。
12. 作为记录者，我希望同一天能够新增多条记录，以便独立记录不同次发生的事情。
13. 作为记录者，我希望能补记过去的日期，以便忘记当天填写时也能补全。
14. 作为记录者，我希望未来日期不能保存记录，以便月度回顾表示已发生的事情。
15. 作为记录者，我希望保存后立即看到记录和更新的月度数字，以便确认保存结果。
16. 作为记录者，我希望刷新或重新打开后仍能读到记录，以便持续积累内容。
17. 作为记录者，我希望逐条编辑已有文字，以便纠正错误和补充细节。
18. 作为记录者，我希望把记录移动到另一天，以便修正记错的日期。
19. 作为记录者，我希望同一天按创建顺序排列，以便修改不会让原有顺序混乱。
20. 作为记录者，我希望删除不需要的记录，并能在短时间内撤销，以便纠正误操作。
21. 作为记录者，我希望删除或移动后日历标记和统计一起变化，以便看到的数据始终一致。
22. 作为记录者，我希望没有记录的日期或月份显示清楚的空状态与新增入口，以便知道下一步能做什么。
23. 作为本地使用者，我希望无需注册或登录即可记录，以便直接开始使用。
24. 作为本地使用者，我希望记录留在当前设备的浏览器中，以便自己持有内容。
25. 作为离线使用者，我希望首次完整加载后断网仍能打开、阅读、记录和修改，以便网络不影响随手记。
26. 作为手机用户，我希望在浏览器支持时能添加应用到桌面，以便更快进入。
27. 作为导出者，我希望选择要导出的月份，以便生成对应月份的月度回顾。
28. 作为导出者，我希望默认选择本月全部记录，并在导出前排除个别记录，以便控制分享内容。
29. 作为导出者，我希望导出前看到完整且可滚动的预览，以便检查内容、顺序和范围。
30. 作为导出者，我希望月度长图同时呈现月历、记录天数、记录条数和每日原文，以便一眼了解这个月。
31. 作为导出者，我希望图片写有“瞎JB记”和年月，以便保存以后仍能辨认来源和日期。
32. 作为导出者，我希望较长内容自动拆成有顺序的多张图片，以便所有记录都能完整保存。
33. 作为导出者，我希望长记录、多行内容和中文标点不被裁切，以便导出内容忠实于原文。
34. 作为导出者，我希望同一筛选范围可以切换图片与纯文字导出，以便不用重新选择记录。
35. 作为导出者，我希望复制按日期整理的纯文字，以便粘贴到聊天或其他应用。
36. 作为导出者，我希望下载 UTF-8 的 .txt 文件，以便长期保存和继续处理。
37. 作为数据所有者，我希望导出所有记录的备份，以便浏览器清理或换设备后还能恢复。
38. 作为数据所有者，我希望恢复备份时明确知道现有数据会整体替换，以便理解操作影响。
39. 作为数据所有者，我希望替换前先下载当前数据备份，以便保留恢复前的内容。
40. 作为数据所有者，我希望恢复后完整读回备份记录且不与现有记录混合，以便避免重复和残留。
41. 作为数据所有者，我希望无效备份或写入失败时现有数据保持完整，以便恢复不会造成数据丢失。
42. 作为记录者，我希望保存失败时保留文字和日期并明确提示，以便重试时无需重新输入。
43. 作为导出者，我希望复制、下载或生成图片失败时得到明确反馈并保留筛选，以便调整后重试。
44. 作为手机用户，我希望输入时使用系统键盘，主要操作不被键盘遮住，以便舒适编辑。
45. 作为用户，我希望按钮有清晰名称、文字有可读对比度且减少动态效果设置生效，以便可靠操作。

## Implementation Decisions

### 已确认的产品与交互约定

- 领域统一使用“记录”“月度回顾”“月度长图”“文字导出”“记录天数”“记录条数”“备份”“恢复”。记录对应一次独立发生的事情，一条可包含多个项目。
- 首页是单月七列日历，沿用设计稿的周一至周日排列；所选日期高亮。每格最多显示两条原文摘要，截断可通过当天详情读全文，超过两条明确展示剩余数量。
- 记录字段以日期和自由文字为核心，不强制运动项目、分类、时长、距离、时间点等结构化输入。不推断文字中的运动次数。
- 当天记录按创建先后排序；修改文字不改变创建顺序，调整日期后在目标日期保持同一排序规则。
- 记录只能属于今天或过去。页面月份切换不等同于允许未来记录。
- 记录天数按所选自然月内有记录的不同日期计算；记录条数按记录数量计算，修改文本中的项目数量不改变条数。
- 新增、编辑、调整日期、删除和撤销均须同步更新日历、详情与受影响月份的统计。
- 删除提供短暂撤销。撤销时长属于实现细节，不虚构为已经讨论过的数值；操作反馈必须可见。
- 文字导出按年月标题、概览、日期分组和逐条原文组织，支持复制与 .txt 下载；保留换行和中文，不自动总结改写。
- 图片导出带产品名、年月、月历、记录天数、记录条数以及按日期排列的完整文字；必要时拆成多图，不能只导出当前预览可见区域。
- 备份覆盖所有月份的记录，不受月度分享筛选影响。恢复是整体替换，不合并，不做记录去重。
- 恢复前明确提示替换含义，并先触发当前数据的备份下载；用户取消恢复不改变数据。
- 首次完整加载之后可离线使用，支持添加到手机桌面；首次打开仍需获取应用资源。
- 视觉采用已完成设计稿的暖纸底、墨黑、酸橙色和字体层次。既有静态稿仅是界面基线，示例数据、假键盘和不可操作按钮不属于现成业务实现。
- 设计稿没有绘制的纯文字模式、筛选、空状态、删除撤销、恢复确认和长图拆分仍属于本规格必需范围，延续同一视觉语言补齐。

### 为实现上述约定提出的工程方案

以下为规格中的实现建议，尚无对应业务代码；不将其描述为用户已选定的技术栈。

- 逻辑边界分为：记录读写、日历与月度回顾、导出与预览、备份恢复、离线应用外壳。可在同一小型前端中实现，避免为这些边界引入独立服务。
- 数据模型需要稳定标识、所属日期、原始文字和稳定创建顺序；修改时间可供内部使用，不能冒充事件实际发生时间。不因用户修改日期重建记录身份。
- 所属日期按设备本地民用日期处理，不把日期当 UTC 时间点转换；跨时区或跨午夜不得让已经保存的所属日期漂移。
- 建议采用浏览器持久化数据库保存记录，事务提交后才展示保存完成；离线资源缓存与记录数据分开处理。具体框架、库和存储 API 由实现时选择，不在本规格无依据地锁定。
- 不新增账号服务、远端记录 API 或云端数据库；资源缓存覆盖页面、必要脚本和样式，正常离线运行不依赖网络字体或远程素材。
- 备份使用可校验、带格式版本的结构化数据；恢复前验证全部内容，事务性替换，避免先清空后导入导致部分失败。
- 浏览器无法确认文件是否最终被用户保留；恢复前应触发下载并给予用户保留副本的机会。若备份生成或下载流程报错，不继续覆盖。
- 图文导出共用一份按日期和创建顺序排列的筛选结果。建议筛选后概览、月历标记和正文均按已选记录重算，排除的内容不得泄露到任何导出部分。
- 预览与最终导出共用内容模型；图片布局按实际文字测量，拆分时重复必要年月和页序，不能丢条、重复正文或切断字行。
- 空白输入不生成无意义记录；长文本、换行和特殊字符按文字处理，不解释为 HTML。
- 保存、导出与恢复错误给出准确反馈，保留当前输入或选择；操作成功不得只改变页面但实际没有持久化。
- 主操作按钮提供短促按压反馈；日期切换反馈与详情更新关联；编辑界面使用轻量进出动效。减少动态效果时直接显示最终状态，业务状态不等待动画。
- 实现使用系统键盘，不实现设计稿中用于说明输入状态的假键盘。手机安全区、软件键盘和内容滚动不能遮挡保存或完整记录。

## Testing Decisions

已确认的测试入口：以真实浏览器中的用户行为作为一个主要验收边界，通过真实界面操作和下载文件观察结果；仅在故障测试中控制浏览器存储或剪贴板等外部能力。用户已确认采用此入口。

- 当前项目没有业务代码、测试框架或可沿用的测试入口；只有已做视觉检查的三屏静态设计。不能把静态截图检查当成功能测试先例。
- 好的测试验证用户能看到的数据、刷新后读回的结果和实际导出文件，不断言私有函数、组件层级、CSS 类名或存储内部调用次数。
- 记录读写验收：同一天新增多条、多行文字、修改、移动到其他日期、删除撤销；每次检查月历、详情和统计一致，并刷新或重开验证持久化结果。
- 日期验收：今天、历史日期、未来日期限制、月末与年末、跨午夜以及设备时区变化；既有记录的所属日期保持不变，统计只计目标月份。
- 统计验收：一天多条只增加一个记录天数；一条写多个项目只计一条；移走或删除某日最后一条记录时，两个受影响月份分别正确更新。
- 自由文字验收：长中文、多行、空白输入、标点和看起来像 HTML 的字符串；原文保存、展示和导出一致，作为文本而非脚本执行。
- 离线验收：首次在线完整加载后关闭页面，断网重新打开，完成读取、新增、编辑和刷新读回；不能只测试已打开页面短暂断网。
- 图片验收：检查实际下载图片而非仅看预览；包含正确月份、筛选后的月历与统计以及完整原文。用足够长的真实中文内容触发拆图，按顺序核对不漏不重、无裁切和重叠。
- 文字验收：读取实际 .txt 文件，检查 UTF-8、日期分组、顺序、换行和筛选一致；复制结果与同范围文件内容一致。
- 筛选验收：排除的记录不出现在图片、纯文字、导出统计或月历标记中；来回切换导出格式不丢筛选；预览与实际文件一致。
- 备份恢复验收：先备份跨月多条数据，再更改本地数据，恢复后只保留备份内容；覆盖前可取得当前数据备份。取消、格式错误、不支持版本和事务写入失败时原数据不变。
- 故障验收：浏览器层模拟存储写入失败、剪贴板不可用和导出失败；保存失败不能显示已保存或丢输入，其他操作失败保留筛选并能重试。不为测试引入新的生产设置入口。
- 移动端验收：以 390px 宽度设计基线并补查更窄视口、较长当天记录和六行月份；检查完整文字可滚动阅读、操作不遮挡、可访问名称、对比度、系统键盘和减少动态效果。
- 添加到桌面及安装后的离线启动需要在目标手机浏览器实际验收；浏览器自动化不能替代平台安装流程检查。
- 测试针对记录、月度回顾、导出、备份恢复和离线流程的外部行为，不再为每个内部模块另建一套同义验收入口。必要的复杂排版检查可补充低层测试，但不能替代实际文件验证。

## Out of Scope

- 登录、账号、云同步、跨设备自动同步、多人共享和协作。
- 固定运动表单、分类体系、自动分类或总结、运动次数识别、时长距离热量统计。
- 未来计划、待办、完成状态、提醒通知、打卡连续天数或目标系统。
- 图片、音视频或其他附件输入，富文本编辑器。
- 备份合并、自动去重、远端备份或永久回收站。
- Excel/CSV 导出、自定义主题编辑器、额外视觉方向和桌面专用多栏产品。
- 本规格不执行产品实现、部署、购买服务或新建远端代码仓库。

## 导出范围扩展（2026-11-04）

用户新增要求覆盖此前仅按月导出的限制：提供本年、本月、本周、今日、自定义范围五种选择，默认本月，以设备本地日期为准。本周周一至周日；快捷选项表示完整自然周期。自定义包含首尾两天，结束日期不得早于开始日期，最多一个完整自然年，闰年可含366天。

图片与文字导出共用范围和逐条筛选，切换格式保留筛选，改变范围默认选择范围内全部记录。无效范围必须阻止预览与导出，不得导出上一次有效范围的旧内容。起止日期写入预览、文件名和实际文件，跨年记录按完整日期分组。单月图片保留日历，跨月以月份日期矩阵展示分布，并继续自动拆图。范围内无记录时显示空状态、禁用导出；备份恢复仍独立覆盖全部月份。
